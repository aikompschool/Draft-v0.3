# Міфопоетичний Агент v0.3 — Жива Пам'ять

v0.3 додає до каркаса v0.2 реальну версійність Слідів і повернення учасника до того, що змінилося без нього.

Ключова фраза версії:

> **Те, що ти залишив, жило без тебе.**

## Що працює

- усе базове з v0.1;
- `/api/chat` і Structured Output v0.2;
- кандидат у Слід і людське підтвердження;
- спільний Архів;
- `traceVersions`;
- `traceEvents`;
- `participantTraceState`;
- інший учасник може зустріти й продовжити Слід;
- стара версія лишається видимою;
- екран **«Поки тебе не було»**;
- повернення первинного учасника;
- `alive / sleeping / released`;
- історія версій у UI;
- базовий TraceLink і Кандидат у Простір з v0.2 збережені.

## Мінімальна Жива Петля v0.3

1. Учасник A залишає спільний Слід v1.
2. Учасник B відкриває Архів і зустрічає цей Слід.
3. B створює v2 — попередня версія не зникає.
4. A повертається.
5. У розділі **«Повернення»** бачить:
   - свою початкову версію;
   - поточну версію;
   - кількість нових дотиків.
6. A обирає:
   - **Живе**;
   - **Змінилося — продовжити**;
   - **Відпускаємо**.

## Запуск

Потрібен Node.js 20+.

```bash
cd mythopoetic_agent_v03
node server.js
```

Відкрити:

```text
http://localhost:8080
```

Без `OPENAI_API_KEY` працює локальний fallback. Уся механіка Живої Пам'яті працює без LLM.

Із LLM:

```bash
export OPENAI_API_KEY="..."
node server.js
```

## Нові API v0.3

### Створити Слід

`POST /api/traces`

Передається псевдонімний `participant_id`.

### Зустріти Слід

`POST /api/traces/:id/encounter`

### Продовжити Слід

`POST /api/traces/:id/continue`

Створює новий запис у `traceVersions`, не переписуючи старий.

### Повернення

`GET /api/return?participant_id=...`

Повертає тільки зміни в Слідах, походження яких належить цьому псевдонімному учаснику і які були продовжені Іншими після останнього повернення.

### Підтвердити повернення

`POST /api/traces/:id/ack`

### Змінити стан власного Сліду

`POST /api/traces/:id/state`

Стани MVP:

- `alive`;
- `sleeping`;
- `released`.

## Дані v0.3

`shared-data.json` містить MVP-структури:

- `traces` — поточна форма кореневого Сліду;
- `traceVersions` — повна дорога версій;
- `traceEvents` — культурні події;
- `participantTraceState` — відношення псевдонімного учасника до Сліду;
- `traceLinks`;
- `spaceCandidate`;
- `spaces`;
- `agentChanges`.

`participantTraceState` не є психологічним профілем. Він зберігає тільки технічне відношення до конкретного Сліду: побачив / продовжив / повернувся / відпустив.

## Перевірено

Автоматично перевірено API-сценарій:

`A -> v1 -> B encounter -> B v2 -> A return -> A ack`.

Після `ack` повернення зникає зі списку нових змін, але історія версій залишається.

## Межа статусу [Є]

**Технічно v0.3 = [Є].**

Культурно v0.3 стане **[Є / ЖИВО]** після першого реального тесту, де учасник сам захоче повернутися до Сліду й відреагує на зміну Іншим.

Це не можна чесно замінити автоматичним тестом.
