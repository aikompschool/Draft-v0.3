# СТАН ПАКЕТУ: що вже є, що будуємо, що попереду

## [Є] v0.1 — Жива Петля

У коді й архітектурі вже є:

- Поріг першої зустрічі;
- локальна Складка з Агентом;
- кандидат у Слід;
- людське підтвердження / переписування / відпускання;
- спільний Архів;
- базовий Слід ↔ Слід;
- Кандидат у Простір;
- рішення спільноти щодо Простору;
- видима історія змін Агента.

- `POST /api/chat`;

- Structured Output;
- `message`;

- `trace_candidate`;

Для реального production-запуску питання API, хостингу, БД, privacy/safety та роботи з неповнолітніми ведуться в окремому живому файлі питань.

## [Є / ТЕХНІЧНО] v0.3 — Жива Пам'ять

Реалізовано:

- `traceVersions` — кожна зміна Сліду є окремою версією;
- `traceEvents` — створення, зустріч, продовження, повернення, сон, відпускання;
- `participantTraceState` — лише відношення учасника до конкретного Сліду, без психологічного профілю;
- псевдонімний локальний participant ID для повернення;
- екран «Поки тебе не було»;
- навігаційний індикатор нових змін;
- історія версій Сліду;
- інший учасник може «зустріти й продовжити» спільний Слід;
- первинний учасник бачить, що сталося без нього;
- дії повернення: «Живе» / «Змінилося — продовжити» / «Відпускаємо»;
- стани `alive / sleeping / released`;
- API-петля A -> v1 -> B -> v2 -> A return;
- стара версія не стирається при появі нової.

Автоматичним тестом пройдено повний технічний цикл:

`A створює v1 -> B зустрічає -> B створює v2 -> A отримує return summary -> A підтверджує повернення`.

### Що ще потрібно, щоб v0.3 стало [Є / ЖИВО]

Провести цикл із реальними учасниками й перевірити, що повернення виникає не лише тому, що кнопка існує, а тому що Слід справді породив Тягу:

> «Що сталося з тим, що я залишив?»

Це культурна атестація, яку код не може замінити симуляцією.
